## 业务主管任务分配验收

- 权限来源：Access 只负责登录；服务端每次从真实 `members` 表取得 active 状态、`staff_role` 与 permissions。ALAN 是 sales，不具备成员管理、设置、部署或 Outreach review 权限；Codex/service 不具备 assign。
- 范围：ALAN 团队读取 6 条隔离样本时返回全部客户、任务与 3 名合格接收人；普通业务员无本人任务时返回 0/0、`can_assign=false`、assignees 为空。任务执行仍以 owner 为准，ALAN 只能开始和提交本人任务。
- 状态与 CAS：unassigned 分配后变 pending；pending 可转派；in_progress/needs_more 仅 boss + `force=true` + 非空原因；submitted/reviewed 永久返回 409；旧 revision 返回 409。
- 原子性：隔离 D1 查询显示每次成功后 task.owner 与 lead.owner 相同，task revision 和 lead version 同步递增；未通过接收人和状态检查时两表均不变。
- 批量与审计：一次 3 项请求返回 total=3、succeeded=2、failed=1，失败项不回滚成功项；accepted/rejected 审计均包含操作者、任务、客户、原/新负责人、原因、状态和服务器时间。
- 界面：仅 `viewer.can_assign=true` 显示“任务分配”；支持单选/多选/全选、企业/城市/状态/当前负责人、接收人选择、确认摘要和服务器逐项回执。普通业务员响应不下发接收人列表，分配 API 另有 403 服务端保护。
- 部分失败：合成批次实际返回 `matched=1 + needs_more=1`、状态 `partial`；合格旧客户追加来源、复用原任务，缺联系方式条目给出具体补项；重复投递仍为同一 2 个批次条目。
